What ResultTrack Does

Four workflows, one grading engine

Every result in ResultTrack passes through the same grading engine — so a score means the same thing whether a lecturer just typed it in or a student is viewing it a year later.

Score Entry

Lecturers enter CA and exam scores per student, per course. Out-of-range values are caught before they're saved, not after.

Automatic Grading

A single computeResult() function applies the 30:70 CA-to-exam weighting and the grading scale consistently, every time.

Student Result View

Students see their CA score, exam score, and final grade as soon as it's approved — no waiting on a noticeboard.

Discrepancy Flagging

If a result looks wrong, a student can flag it directly. The lecturer sees exactly which entry is in question and resolves it in place.

One Grading Policy

The grading scale, weighting, and pass marks live in a single configuration object — change it once, and it applies everywhere consistently.

Built to Connect to a Backend

Every data operation runs through an async request wrapper, so swapping in a real backend later doesn't mean rewriting the front end.

FAQs

What is ResultTrack, exactly? +

ResultTrack is a result management system for Nigerian universities and higher institutions. It covers four things: a lecturer enters CA and exam scores, the platform computes the grade automatically, students see their result the moment it's approved, and a student can flag a result that looks wrong so a lecturer can review it.

How does grading actually work? +

Every result runs through one grading engine, so a score is computed the same way whether it's typed in manually or uploaded in bulk. The current MVP uses a 30:70 CA-to-exam weighting, with the scale kept in a single configuration so it can be adjusted for a specific institution's policy.

What happens if a student disagrees with a result? +

The student flags the specific result directly from their portal. The flag goes to the lecturer who entered it, with the exact CA score, exam score, and computed grade attached — so there's no back-and-forth trying to figure out which entry is being questioned.

Is student information kept secure and private? +

Result data is encrypted at rest and in transit. Students can only see their own record; lecturers see only their own courses; role-based permissions and an audit trail apply across the platform.

Is ResultTrack connected to a live backend yet? +

The current build is a working front-end MVP with a request layer built to swap in a real backend without a rewrite. That integration — and university-specific onboarding — is the next stage of the project.
